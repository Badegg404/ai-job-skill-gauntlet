# 岗位知识库维护说明

本项目的岗位知识库是一个**可长期维护的 JSON 数据库**，位于 `web/job_knowledge.json`。LLM 面试官在面试时按岗位加载对应的知识库，作为出题、追问、评分的参考。

## 一、数据在哪

- **数据本体**：`web/job_knowledge.json`（唯一数据源，改这里就行）
- **加载器**：`web/job_knowledge.js`（前端启动时 `fetch` 这个 JSON，填到全局 `JOB_KNOWLEDGE`）
- **调用方**：`web/prompts.js`（`buildInterviewerSystem` 把岗位职责/技能/知识图谱要点注入面试官 SYSTEM 提示词）

> ⚠️ 不要在 `job_knowledge.js` 里直接改岗位数据——那里只有加载逻辑和通用追问技巧 `INTERVIEWER_TACTICS`。改岗位一律改 JSON。

## 二、JSON 结构（schema）

```json
{
  "schemaVersion": 2,
  "name": "AI 岗位面试知识库",
  "description": "……",
  "updatedAt": "2026-01-01",
  "jobs": [
    {
      "id": "agent_engineer",          // 唯一 id，小写英文+下划线，前端用它定位岗位
      "name": "Agent 工程师",           // 展示名
      "category": "应用层 · Agent",     // 分类（应用层/平台层/算法层/质量保障）
      "summary": "一句话职责概述",        // 岗位卡片上显示
      "systemRole": "面试官角色定位文字",    // 【重要】该岗位的面试官角色定位（强调考察重点+追问风格，非罗列职责）
      "duties": ["职责1", "职责2"],      // 岗位职责（systemRole 缺失时作为回退）
      "skills": ["技能1", "技能2"],      // 核心技能（systemRole 缺失时作为回退）
      "dimensions": { "Agent 核心机制": 5, "面试表达力": 3 },  // 考察维度 + 权重（数值=权重）
      "knowledgePoints": ["知识点1", ...],  // 知识图谱要点（出题深挖的依据）
      "sampleQuestions": ["典型问题1", ...], // 参考弹药 + 兜底题：喂给出题 prompt 参考，LLM 失败时兜底
      "followUpHints": ["追问方向1", ...],   // 追问方向 → 注入追问 prompt
      "scoring": { "优秀": 90, "良好": 75, "及格": 60, "标准": "……" },  // 评分标准 → 注入评分 prompt
      "realQuestions": ["面试真题1", ...]     // 大厂面经真题，供出题风格参考
    }
  ]
}
```

### 各字段的用途

| 字段 | 谁来用 | 用途 |
|---|---|---|
| `id` / `name` / `summary` / `category` | 前端岗位选择页 | 卡片展示 |
| `systemRole` | `buildInterviewerSystem` | **面试官角色定位（优先）**：手写、针对该岗位考察重点+追问风格的定位 |
| `duties` / `skills` | `buildInterviewerSystem` | 面试官角色 SYSTEM（`systemRole` 缺失时的回退） |
| `dimensions` | 岗位分析 / 开场展示 | 考察维度（`key` 是维度名，`value` 是权重） |
| `knowledgePoints` | `buildInterviewerSystem` | 面试官「知识图谱要点」，据此深挖出题 |
| `sampleQuestions` | `buildInterviewQuestionPrompt` 参考 + `generateNextQuestion` 兜底 | 出题参考弹药（打乱后喂给 LLM）；LLM 失败/超时时兜底 |
| `followUpHints` | `buildInterviewFollowPrompt` | 追问方向 |
| `scoring` | `buildInterviewScorePrompt` | 评分标准（优秀/良好/及格阈值 + 判分细则） |
| `realQuestions` | `buildInterviewQuestionPrompt` | 出题风格/深度参考 |

## 三、如何增加一个新岗位

1. 打开 `web/job_knowledge.json`
2. 在 `jobs` 数组里加一个对象，**字段参照上面的 schema 填全**（`id` 唯一、`name` 唯一）
3. 顺手把 `updatedAt` 改成当天日期
4. 保存后重新打包（`run_tests.sh` + PyInstaller）

示例（最小可用的新岗位）：

```json
{
  "id": "data_engineer",
  "name": "数据工程 / AI 数据工程师",
  "category": "数据层 · 数据工程",
  "summary": "训练数据管线与数据质量治理",
  "duties": ["构建训练数据管线", "数据清洗与质量治理"],
  "skills": ["数据工程", "数据标注规范", "LLM 原理与 API"],
  "dimensions": { "数据工程": 5, "AI 应用开发": 3, "面试表达力": 2 },
  "knowledgePoints": ["微调数据工程：收集/清洗/标注/Garbage In Garbage Out", "数据标注规范与质检"],
  "sampleQuestions": ["你们训练数据是怎么清洗的？", "数据质量如何评估？"],
  "followUpHints": ["追问数据分布漂移", "追问数据版本管理"],
  "scoring": { "优秀": 90, "良好": 75, "及格": 60, "标准": "有数据工程实战，能量化评估数据质量" },
  "realQuestions": ["如何设计一个高质量微调数据集？"]
}
```

## 四、如何优化一个已有岗位

- **补职责/技能**：直接改 `duties` / `skills` 数组（这些会直接进面试官 SYSTEM，写得越具体越好）
- **补知识图谱要点**：把该岗位对应的最新知识点填进 `knowledgePoints`（参考《AI 大模型应用开发工程师知识图谱》或网上最新 JD）
- **补参考题**：往 `sampleQuestions` 加「预设真实业务场景 + 问怎么做」风格的题（既是出题参考弹药，也是 LLM 失败时的兜底）
- **调评分**：改 `scoring` 的阈值和标准
- **补真题**：往 `realQuestions` 加最新大厂面经题

> 💡 除了手动维护，导入学习资料时系统会自动用 LLM 判断资料最贴近哪个岗位、并提炼 3 道该岗位的场景面试题，存进本机 `jobExtraQuestions`，面试该岗位时自动并入参考弹药。

## 五、字段改动要同步的地方

改了字段名/结构（比如把 `duties` 改名），要检查这些消费方是否跟着改：

- `web/prompts.js`：`buildInterviewerSystem` / `buildInterviewQuestionPrompt` / `buildInterviewFollowPrompt` / `buildInterviewScorePrompt`
- `web/exam.js`：`renderJobSelect` / `startJobInterview` / `generateNextQuestion` 兜底

> 建议：只「增字段」「改内容」，不要「删字段」「改名」，避免遗漏消费方。

## 六、数据来源

- 岗位职责/技能：AI 行业招聘 JD（网上搜索 + 沉淀）
- 知识图谱要点：`AI大模型应用开发工程师知识图谱.pdf`（在 `~/Downloads/AI大模型应用开发工程师day1资料/`）
- 面试真题：大厂面经 + 招聘题库

每次补充后更新 `updatedAt`，方便追踪最近一次维护时间。
