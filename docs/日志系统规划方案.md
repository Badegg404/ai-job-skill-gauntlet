# 日志系统规划方案（v1 草案）

> 目的：把「只覆盖导入的 import-debug.log」升级为**全功能、可追踪、可回放**的日志体系。
> 原则对齐 skill 方法论 §3.9：日志是 LLM 应用的第一公民——全链路事件化、响应体快照、落盘服务端、别静默吞错误、日志即产品。
> 零新依赖：后端用 Python stdlib `logging`（RotatingFileHandler 自带轮转），前端自研轻量 Logger。

---

## 一、现状盘点

### 已有（做得好，保留）
| 位置 | 内容 |
|---|---|
| 前端 `reportDebug(tag,payload)` | 唯一日志通道：POST /api/import-debug → 落盘 `~/.exam-center/users/{uid}/import-debug.log`（JSONL，每行 `{at,tag,payload}`） |
| `llmJSON` 内事件化 | LLM 交互已有全链路：llm-start / llm-retry / llm-net-retry / llm-ok / llm-fail / llm-empty / llm-empty-final / llm-partial-final；解析 0 题时带响应体快照 contentHead（前 1500 字） |
| 后端访问日志 | SimpleHTTPRequestHandler 默认行（`[course] ...` → stderr） |

### 缺口（本次要补的）
1. **前端无全局错误捕获**：`window.onerror` / `unhandledrejection` 未接，运行时 JS 异常**静默丢失**；前端零 `console.*` 使用
2. **后端业务层零日志**：每个 /api/* handler 不记录「谁、何时、调了什么、结果如何、耗时多少」；异常全靠肉眼
3. **静默吞错多**：后端大量 `except Exception: pass`（改名镜像/删除镜像/reset 清理等）；前端 `catch(() => {})`（course-save、reportDebug 自身等）——违反方法论「catch(()=>{}) 是调试杀手」
4. **非 LLM 功能无日志**：考核作答/判分、面试流程（start/finish/评分失败）、目录增删改、设置保存、reset-all、LLM 连接测试——出问题只能盲猜
5. **无会话关联**：一次导入/考核/面试的日志散落，无法按流程串起来看
6. **无日志查看入口**：只能手动开文件；无 GUI 入口、无过滤/导出/清空
7. **无轮转**：import-debug.log 无限追加（当前 36KB/163 行，含快照会持续膨胀）

---

## 二、设计目标

- **可追踪**：每个功能（导入/考核/面试/目录/设置/系统）都有事件日志，问题能定位到具体一步
- **可回放**：LLM 请求/响应快照、错误 traceback、会话链完整可回看
- **可关联**：一次流程一个 sessionId，日志按 session 聚合
- **可查看**：GUI「诊断中心」页内过滤/导出/清空，不用开终端
- **零依赖 + 低侵入**：stdlib logging + 前端单文件 logger；不重构现有代码结构
- **不吞错**：所有失败路径至少一条 warn/error 日志

---

## 三、总体架构

```
浏览器（原生 JS）
  ├─ Logger（前端单例）：log/warn/error 组装 JSONL 行
  │     ├─ 功能打点（import/exam/interview/dir/settings）
  │     ├─ 全局错误捕获（window.onerror + unhandledrejection）
  │     └─ reportDebug 升级为 Logger 内部实现（旧调用点零改动）
  │     └─ 批量上报（≤50ms 缓冲合并，尽力而为，失败静默）
  └─ POST /api/log   ← 新增统一上报接口（替代 /api/import-debug）

后端（Python stdlib logging）
  ├─ logs/app.log         全局系统日志（启动/端口/未捕获异常）~/.exam-center/logs/
  ├─ users/{uid}/logs/activity.log   每用户活动日志（业务事件，JSONL）
  ├─ 统一请求日志：do_GET/do_POST 分发处记录（method/path/uid/状态/耗时）
  ├─ 统一异常日志：handler 顶层 try/except 记录 traceback
  └─ RotatingFileHandler 轮转（单文件 2MB × 5 份）
```

**数据流**：前端事件 →（批量上报）→ /api/log → 用户 activity.log；后端自身事件直接写 app.log / activity.log。

## 四、日志格式规范（JSONL 单行）

每行一个 JSON，字段统一：

```json
{
  "at": "2026-08-20T23:11:38.588402",   // ISO 时间
  "level": "info|warn|error",           // 级别
  "session": "imp_20260820_2301",       // 会话 id（一次导入/考核/面试/测试）
  "tag": "exam.submit",                 // 事件名（见 §六 事件目录）
  "msg": "用户提交答案",                 // 一句话描述（日志即产品，报错提示由此生成）
  "payload": { ... },                   // 结构化数据（限制大小，见 §九）
  "durMs": 1234,                        // 可选：耗时（慢请求/LLM 调用）
  "uid": "dev_9937b387036a"             // 可选：用户（app.log 需要）
}
```

兼容性：与现有 import-debug.log 行格式（`{at,tag,payload}`）超集兼容，旧文件可被诊断中心读取。

## 五、前端 Logger 设计（web/logger.js 新文件，~80 行）

```js
const Logger = {
  session: null,             // 当前流程 sessionId
  buffer: [],                // 批量上报缓冲
  timer: null,

  begin(kind) {              // 新流程开始：imp_/exam_/iv_/test_ + 时间戳
    this.session = kind + "_" + Date.now().toString(36);
    return this.session;
  },
  log(level, tag, msg, payload = {}) {
    const row = { at: new Date().toISOString(), level, session: this.session, tag, msg, payload };
    this.buffer.push(row);
    // 浏览器 console 同步镜像（仅 debug 用，不影响落盘）
    if (level === "error") console.error(tag, msg, payload);
    else if (level === "warn") console.warn(tag, msg, payload);
    this.flushLater();
  },
  flushLater() {             // ≤50ms 合并批量 POST，避免每条一个请求
    if (this.timer) return;
    this.timer = setTimeout(() => { this.timer = null; this.flush(); }, 50);
  },
  async flush() {
    if (!this.buffer.length) return;
    const rows = this.buffer.splice(0);
    try {
      await fetch("/api/log", { method: "POST", headers: {"Content-Type":"application/json"},
        body: JSON.stringify({ uid: UID || "", rows }) }).catch(() => {});
    } catch (e) {}
  },
  info(tag, msg, payload) { this.log("info", tag, msg, payload); },
  warn(tag, msg, payload) { this.log("warn", tag, msg, payload); },
  error(tag, msg, payload) { this.log("error", tag, msg, payload); },
};

// 全局未捕获异常：JS 运行时错误 → error 日志（含 stack + url + line），这是「每个功能问题都能被追踪」的兜底
window.addEventListener("error", (e) => Logger.error("sys.uncaught", "未捕获异常: " + e.message, {
  stack: String(e.error && e.error.stack || "").slice(0, 2000), url: e.filename, line: e.lineno }));
window.addEventListener("unhandledrejection", (e) => Logger.error("sys.unhandledrejection", "未处理的 Promise 拒绝", {
  reason: String(e.reason && e.reason.message || e.reason).slice(0, 1000) }));
```

要点：
- `reportDebug(tag,payload)` 改为 `Logger.error/info/warn` 内部实现（旧调用点零改动，import 诊断 tag 保持不变）
- **批量上报 + 尽力而为**：本地服务器，丢几行可接受，绝不阻塞主流程
- **API key 永不进日志**：任何 payload 组装处不传 key（现状 llm-start 已合规，加一条开发约定）

## 六、事件目录（tag 体系：域.动作）

| 域 | tag 示例 | 触发点 |
|---|---|---|
| llm.* | llm-start/ok/fail/empty/… | llmJSON 内（现有，保持） |
| import.* | import-start/import-fail/import-done/import-partial/补出题 | 导入主流程 + reGenerateQuestions |
| exam.* | exam-start/exam-submit/exam-grade-llm/exam-grade-code/exam-result/考试中止 | startExam/submitAnswer/llmGrade*/showResult/quitExam |
| interview.* | iv-start/iv-ask/iv-judge/iv-follow/iv-score/iv-fail/iv-finish/评分失败 | startInterview/ask/judge/finishInterview |
| dir.* | dir-create/dir-rename/dir-delete/dir-file-add/dir-file-delete | 目录管理全操作 |
| settings.* | settings-save/test-llm-ok/test-llm-fail | saveLLMSettings/testLLMConnection |
| profile.* | profile-save/reset-all | saveIdentity/resetAllData |
| sys.* | sys.uncaught/sys.unhandledrejection | 全局捕获 |

**打点原则（宁缺毋滥）**：只打「能帮助定位问题」的事件——操作开始/结束、成败、关键数据（题数/分数/轮次）；不追求每行都打。**所有失败路径至少一条 warn/error**（对应现状 audit 的 except:pass / catch(()=>{})）。

## 七、会话关联（sessionId）

- 流程开始时 `Logger.begin("imp"|"exam"|"iv"|"test")`，之后该流程所有日志行带同一 session
- 诊断中心按 session 过滤 → 一次导入/考核/面试的问题**一条链看全**（start→retry→ok→fail）
- 现状已天然可用：llmJSON 的事件本身就按 part 关联，补上 session 后按流程聚合

## 八、后端日志设计（server.py 增量，stdlib logging）

```python
import logging
from logging.handlers import RotatingFileHandler

LOG_DIR = Path(os.environ.get("EXAM_CENTER") or Path.home() / ".exam-center")
# app.log：全局（启动/端口/未捕获），RotatingFileHandler 2MB × 5
# activity.log：每用户（users/{uid}/logs/activity.log），同样轮转
```

1. **统一请求日志**：在 do_GET/do_POST 分发处包一层（before/after）：
   - 记录 `method path uid 状态码 耗时`；耗时 > 2s 记 warn（慢请求预警）
   - 不记录请求体全文（隐私），只记 query/参数摘要
2. **统一异常日志**：`do_GET/do_POST` 顶层 try/except → `logger.exception`（带 traceback）→ 返回 500 JSON。**从此任何 handler 抛异常都有记录**
3. **except:pass 审计**（现状清点，逐个补 warn）：
   - server.py：改名镜像 472-473、import-debug 写盘 496-497、删镜像 522-523、reset 清理 548-559、dir-file-delete 相关
   - 前端 `catch(() => {})` 同样逐个审：course-save 1396、reportDebug 自身、llmJSON 内部 catch
4. **/api/log 新接口**：接收前端批量行，校验 uid 后逐行写 activity.log（**兼容保留 /api/import-debug**，旧版前端/旧文件不破坏）
5. **多用户**：activity.log 在用户目录 → reset-all **不清 logs/**（诊断日志是排障资产，不清；清理由用户手动在诊断中心操作）

## 九、存储 / 轮转 / 隐私 / 性能

- **落盘位置**：
  - `~/.exam-center/logs/app.log` —— 全局系统
  - `~/.exam-center/users/{uid}/logs/activity.log` —— 用户活动
- **轮转**：RotatingFileHandler 单文件 2MB × 5 份（导入快照大时自动滚，不手动清）
- **隐私**：本地文件；payload 快照保持截断（LLM 原始内容前 1500 字、错误前 800 字、stack 前 2000 字）；API key 绝不入日志；prompt 全文不落（只记 promptLen，现状已如此）
- **性能**：前端批量上报（50ms 合并）；后端写盘用 logging（异步性足够）；日志失败不影响业务（reportDebug 现状已 catch）

## 十、GUI「诊断中心」入口（新功能）

- 位置：首页底部/设置页新增「🔍 诊断日志」按钮 → 弹窗或独立视图

## 十二、风险与注意

1. **兼容**：reportDebug 旧 tag 与调用点全部保留，前端升级不破坏旧版后端；/api/import-debug 保留
2. **性能**：日志绝不能阻塞考核/面试主流程（异步 + 批量 + 失败静默）
3. **膨胀**：2MB×5 轮转 + 快照截断，长年使用可控
4. **隐私**：本地单机应用，日志不外传；导出由用户主动
5. **别过度设计**：不引入日志框架、不搞远程日志、不做每分钟级指标——够用、能查、能导出即可
